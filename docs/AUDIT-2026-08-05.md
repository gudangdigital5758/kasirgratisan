# Audit Mendalam KASIRGRATISAN / Profitku — 2026-08-05

> Audit struktur, arsitektur (scalability & maintainability), dan keamanan.
> Basis: `main` @ `d6316e1`. Baseline: `npm test` 30/30 pass, `npm run lint` 25 errors (CI merah), `npm run build` — perlu diverifikasi ulang.

## Ringkasan eksekutif

Kode secara keseluruhan **matang dan terawat**: layering bersih (pages → lib → hooks), transaksi
kasir atomik, fail-closed auth, RLS Supabase lengkap, pemisahan secrets client/server rapi, dan ada
test unit. Tidak ditemukan kerentanan **Critical**. Namun ada 4 masalah nyata yang harus diperbaiki:

1. **CI merah** — `npm run lint` gagal (25 errors) padahal CI menjalankannya di tiap push/PR.
2. **i18n `ms` (Bahasa Melayu) tertinggal jauh** — 342 key hilang (settings 316, products 26).
3. **Harden Worker** — validasi key `app-settings` (injeksi PostgREST) + log PII di `webhook/user-type`.
4. **XSS self** — `document.write` cetak QR menyisipkan nama toko tanpa escape.

## 1. Kualitas Struktur & Arsitektur

### 1.1 Layering & modularitas — BAGUS

| Lapisan | Peran | Contoh |
|---|---|---|
| `src/pages/*` | UI fitur | Cashier, Products, Reports, Settings |
| `src/lib/*` | Domain logic + data | `db.ts`, `cashier-ops.ts`, `backup.ts`, `auth.ts`, `cloud-api.ts` |
| `src/hooks/*` | React hooks | `use-auth`, `use-cloud-auth`, `use-cloud-auto-backup` |
| `src/components/*` | UI reusable | Receipt, ProductPicker, layout/*, ui/* |

**Positif:**
- `cashier-ops.ts` (297 baris) adalah contoh bagus: domain service terpisah dari UI, transaksi
  multi-table Dexie atomik, stok selalu dibaca dari DB terkini, menolak oversell
  (`CashierOpsError`). Persis seperti yang dijanjikan `DECISIONS.md`.
- Schema lokal berversi: 15 versi Dexie dengan upgrade handler bertahap, konvensi soft-delete
  (`isDeleted`), dan kolom siap-sync (`syncedAt`).
- Offline-first dihormati: core POS 100% lokal; `sync.ts` fail-closed (no-op) sampai push/pull
  siap — tidak ada data lokal yang salah ditandai tersinkron.
- Worker dibagi rapi: `index.ts` (routes) + `lib/*` (supabase, backups, lifecycle, notify,
  midtrans, vouchers, admin) + `routes/admin.ts`.
- i18n berbasis namespace JSON per fitur (common, settings, products, dsb.) — struktur sehat.

### 1.2 Scalability — BAGUS untuk skala saat ini, dengan catatan

- **Arsitektur cloud** (Worker + Supabase + R2 + Resend/Fonnte) mudah diskalakan: stateless
  Worker, Postgres terkelola, R2 object storage, cron untuk dunning & cleanup retention 30 hari.
- **Offline-first** menghindari beban server untuk transaksi inti — ini keputusan arsitektur yang
  tepat untuk UMKM (kios dengan koneksi buruk).
- **Catatan:** sinkronisasi antar-perangkat belum ada (keputusan sadar). Ketika ditambahkan,
  konflik merging dan antrian push/pull perlu desain khusus — jangan dianggap sepele.
- **Kuota & limit ditegakkan server-side** (storage quota 2GB, max 50MB/backup, max stores via
  `create_store_with_limit` dengan advisory lock). Skala ke ribuan user aman.

## 2. Kualitas Keamanan

### 2.1 Temuan Positif (dilakukan dengan benar)

- **Secrets hygiene:** Tidak ada secret di client. Hanya `VITE_SUPABASE_URL/ANON_KEY`,
  `VITE_GOOGLE_CLIENT_ID`, `VITE_GA_MEASUREMENT_ID`, `VITE_ONESIGNAL_APP_ID`,
  `VITE_AUTH_API_URL` (semua public-safe). Service role, Resend, Fonnte, Midtrans, WEBHOOK_SECRET
  hanya di Worker secrets. `.env.example` bersih; `.gitignore` menutup `.env.*`.
- **Auth fail-closed:** Worker memvalidasi Bearer via Supabase `/auth/v1/user` (bukan decode JWT
  mentah). Legacy Google JWT dibersihkan & tidak direstore (sesuai DECISIONS 2026-07-30).
- **CORS allowlist:** hanya origin resmi + localhost dev + `capacitor://localhost`.
- **RLS Supabase:** semua tabel `enable row level security`; policy own-row; tabel admin tanpa
  policy client (service-role only); `security definer` dibatasi `set search_path` + revoke dari
  `public/anon/authenticated`.
- **Trust boundary server-side:** harga & voucher dihitung di Worker, bukan client; R2 key
  di-scope per user (`backups/{userId}/{uuid}-...`); kuota & ukuran file (50MB) ditegakkan;
  cleanup metadata gagal → object R2 dihapus (anti-orphan).
- **Webhook Midtrans** memverifikasi `signature_key` SHA512 sebelum fulfill.
- **Admin:** RBAC (`superadmin/support/finance/readonly`) via tabel `admin_users` atau
  `ADMIN_EMAILS` env; ada audit log; rate-limit tidak ada tapi risiko rendah.
- **Backup download/delete** memfilter `user_id` — tidak bisa akses backup user lain.
- **Struktur `cashier-ops`**: cek stok dari DB (anti race), tolak oversell.

### 2.2 Temuan yang diperbaiki

| # | Severity | Temuan | Lokasi | Fix |
|---|---|---|---|---|
| S1 | **Medium** | Injeksi filter PostgREST pada `key` route param | `workers/api/src/index.ts` `GET /api/app-settings/:key` | Validasi key dengan whitelist regex |
| S2 | **Low** | `webhook/user-type` log body penuh (identifier device) | `workers/api/src/index.ts:1127` | Log ukuran/tipe saja |
| S3 | **Low** | Self-XSS: `document.write` cetak QR menyisipkan `store?.name` tanpa escape | `src/pages/settings/CloudOnlineStoreSettings.tsx` (2 tempat) | Escape HTML sebelum interpolasi |
| S4 | **Low** | `console.log` di webhook payment berisi orderId + status (bukan rahasia, tapi sebaiknya ringkas) | `index.ts:1145` | Ringkas (tetap log utk debugging; tidak wajib) |

### 2.3 Catatan (tidak diperbaiki — keputusan sadar / di luar scope)

- **PIN multi-user lokal** = obfuscation device-local (SHA-256 + deviceId salt), bukan security
  server-grade. Ini **sesuai desain** (`DECISIONS.md`) — pengguna dengan akses device bisa buka
  IndexedDB. Bukan bug.
- **Tidak ada rate limiting** di Worker. Untuk volume UMKM saat ini acceptable; pertimbangkan
  limit per-user di masa depan.
- **Tidak ada CSP header eksplisit** — PWA di-hosting Cloudflare Pages (header default).
  Direkomendasikan audit terpisah saat publish.
- **`cordova-plugin-purchase`** ada di dependencies tapi Play Billing nonaktif
  (`playStoreEnabled=false`) dan tidak terpakai → dihapus.

3. **Harden Worker** — validasi key `app-settings` (whitelist regex anti-injeksi PostgREST), sanitasi log
   `webhook/user-type` (tidak log body penuh).
4. **XSS print** — escape nama/identifier toko di template cetak QR (`escapeHtml`).
5. **Hygiene deps** — hapus `cordova-plugin-purchase` (tidak terpakai), pindah `@swc/core` ke devDependencies.
6. **npm audit** 12 → 4 kerentanan:
   - **Diperbaiki:** `@supabase/supabase-js` 2.49.x → 2.112.0 (patched `auth-js`), `postcss` 8.5.25,

     - `sharp <0.35` (high ×2): **tidak ada fix**; hanya dipakai `@capacitor/assets` (build-time
